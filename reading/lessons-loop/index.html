432 lessons, and my agent kept making the same mistake

I had my coding agent write down every mistake. Then I checked whether it was using any of it.

One mistake, written down 33 times.

written
10 November 2026
about
AI agents · memory · engineering workflow
window
432 lessons, 29 October to 9 November 2026, and the first night after the changes

If you use coding agents, you need them to learn from usage. Otherwise you correct the same mistake every week.

So I had a lessons.md loop. Every time my agent got something wrong, it wrote a lesson in a file: what happened, why, what it cost me, and the rule it would follow from then on. I use Claude Code, and agents write most of my code.

I ran that loop for 432 lessons. I recently realised it had been useless.

Why it was useless

The agent was good at writing lessons. It did not do a good job of using them.

Nothing loaded the file. The agent was meant to read the last twenty entries at the start of a session. In the session where I asked how the file gets used, it hadn't.

One mistake shows it. In the terminal, the agent moves to another folder with a bare cd. The session stays there, and a later command runs in the wrong place. The agent first wrote this down on 3 November, and made it a standing rule the same day. A week later, 33 lessons had the same mistake in the title.

The lessons were also wrong about themselves. On 9 November the agent wrote four lessons about this slip. They called it “the third time”, “the fifth time”, “the third time” and “a fourth time”. The file already held 26.

And nothing could check them. Of those 432 lessons, 2 said how the agent knew the lesson was true. None named the session it came from.

What Anthropic measured

On 6 November Anthropic published The components of agent memory. It tests the same idea: give an agent a place to keep notes between sessions, and see what makes those notes worth having.

These are Anthropic's numbers, on their tasks. Mine are further down.

Dreaming is the part I was missing. An agent writes its notes in a hurry, in the middle of a task. Later, when nobody is waiting, a model rereads each note next to the transcript it came from, and fixes what doesn't match. In Anthropic's words, dreaming “gives Claude a way to test its notes against the original transcripts”. It is like rereading last night's diary with your texts open beside you.

The same piece notes that most of Opus 5's entries on that database task paired a rule with the evidence for it. My 432 lessons had the rule and no proof.

What I added

A verifier

A script takes one day's lessons, finds the session that wrote each one, and asks Opus 5.5 whether the lesson matches what happened. It also gets every earlier title, so it can count repeats. It writes a report and never edits the file.

Proof on every lesson

A lesson now ends with how the agent knows, and the session it came from. A repeat count comes from searching the file.

A guard for repeats

A mistake that survives a written rule gets a check that runs before every command and refuses the bad one. The first guard is for cd.

My corrections, sorted

I can be wrong too. If I correct a fact, the agent checks the record before it agrees. If I correct taste, that call is mine, and the newest one wins.

The good stuff too

The agent logs what worked, as well as what went wrong. A file of failures tells it what to avoid. It doesn't tell it what to do again.

why sort my corrections

Many lessons start with me correcting the agent. Anthropic looked at about 38,000 real conversations this spring. Claude was sycophantic in 18% of the ones where the person pushed back, against 9% of the rest. The study is How people ask Claude for personal guidance.

If I push, the agent is more likely to agree with me. Then it writes my mistake down as its lesson.

What got better

The new rules went in at 23:38 on 9 November. By three the next morning, the lessons were already a lot better.

One night, on one person's setup. I would read it as a direction.

The lesson the agent wrote after the refused command says: “one denied call. Nothing ran in the wrong folder.” It counted its repeats from the file, marked its explanation as a guess, and named its session.

A count the agent can't shrink

I wanted one number that tells me whether any of this works. The count of lessons is a bad one, because the agent writes the lessons. It can fall because the agent wrote less.

So I count my corrections, from the transcripts. The first version matched phrases like “no,” and “that's wrong”. I checked it by hand, and it caught about one correction in nine.

The second version has a small model read every message I typed and label it. Over five weeks and 1,501 messages, it found 237 corrections. I checked 40 of its labels by hand, and 31 were clearly right.

17%
of what I type to my agent is me fixing something. It has been steady for three weeks. This is the before number.

What it still misses

The old lessons

Only one day has been through the verifier. The other 430 or so lessons are as unchecked as they were.

It costs

The first pass read about 534,000 tokens for 28 lessons. The agent had told me 187,000.

Nothing retires

No rule ever leaves the file. A wrong lesson gets a correction written after it, and the wrong one stays where a session can still read it.

What I would copy

If you keep a lessons file for a coding agent, add two lines to every lesson: how the agent knows, and which session it came from. Without them, nothing can check the lesson later.

Then check one day of lessons against the transcripts. Mine took an evening to build, and it found ten wrong claims on the first night.

And when the same lesson shows up a third time, build a guard for it. Mine had been written down 33 times.

Numbers come from my own lessons file and session transcripts, 29 October to 10 November 2026. The research figures are from Anthropic's The components of agent memory (6 November 2026) and How people ask Claude for personal guidance (April 2026).
