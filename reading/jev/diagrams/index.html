TypeSafe’s own line. A value near 1 is a strong yes, near 0 a strong no, near 0.5 the model gives both similar odds. $0.042 per million input tokens; output free.

The message, the two questions and both values are TypeSafe’s own worked example from their Noul docs, copied verbatim. Bar length is the value itself against a 0 to 1 track. A Noul carries no separate confidence number, because the distribution has only two outcomes.

Two minds, one sentence

The same line of landing copy, read by a closed list of nouns and by a question.

the line on the page “2,000 bakers already bake with us.”
a closed list of nounscustomers · users · subscribers · members …
bakers is not on the list · no match

one question, no listDoes this say some number of people already use it?
a probability above the 0.5 bar

A list can never finish. A question can.

Every trade has its own noun for a customer. The list has to be widened for each one. The question is already asked.

The sentence is a real leak the noun list missed. On the labelled traction set the list scored precision 0.85 and recall 0.61; the question scored precision 1.00 and recall 0.96 at a 0.5 bar. No per-row probability was published for this one sentence, so none is shown.

The judge decides semantics, code decides policy

Code builds the options and keeps the rule. The model only scores what it is handed.

shipswhat code built
api failure, timeout, bad reply
the line the judge cannot draw

Both ask where a file lives. Only one is what the gate is for.

“where’s it stored”
Jev: yes · policy: yes
“don’t want it exported”
Jev: yes · policy: no
the judge never holds the pen
Any failure ships exactly what code built before.

The model can add a rejection or pick among options. It never grants permission. Untrusted text goes in the state, never in the question.

On one labelled set every false positive at a 0.5 bar was a policy row, not a semantic one: eight of them, each a sentence the model read correctly and the product rule treats differently.

05

Five places I would put a Noul

None of these are built. Each one is a rule I currently keep in my head or in a regex.

01
evals“Does this run meet the criterion as written?” state: one rated card and the rubric line · code does: shows the number beside the human rating, flags the disagreements
02
citations“Does this passage support the quote attributed to it?” state: the quote and the passage it came from · code does: holds the citation back below the bar, never rewrites
03
pr loop“Is this reviewer comment a verdict or an acknowledgement?” state: the comment text alone · code does: starts the fold timer on a verdict, stays quiet on the rest
04
dogfood“Is this observation a defect or a taste call?” state: the note as I typed it · code does: routes defects to the bug list, taste to the backlog
05
journal“Does this entry name a decision?” state: one morning entry · code does: pulls the ones that do into a decision ledger for the week
One question per rule. Code keeps the rule.

Each of these replaces a keyword match or a habit, and each one returns a number my own code still has to act on.

Intentions, not shipped work. None of these has been measured; the point of writing them down is that each is one question I can test against a set I already have.
